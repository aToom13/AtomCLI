Reads a file from the local filesystem, subject to read and external-directory permissions. A supplied path may be missing or inaccessible; errors do not authorize access to another target.

Usage:
- filePath accepts an absolute path or a path relative to the current workspace. Prefer workspace-relative paths for files there; otherwise copy an exact observed absolute path instead of reconstructing it.
- After a missing-file error, locate the target with find in the current workspace before retrying. A denial for an external path does not imply that discovery inside the workspace is denied; do not retry the denied target through another tool.
- By default, it reads up to 2000 lines starting from the beginning of the file
- You can optionally specify a line offset and limit (especially handy for long files), but it's recommended to read the whole file by not providing these parameters
- Text is bounded to 50 KiB per read; long lines within that budget remain complete. Line offsets cannot resume inside a line larger than the byte budget.
- Results are returned using cat -n format, with line numbers starting at 1
- Editable text results (up to Edit's 10 MiB limit) include a full `contentHash`; native execution remembers it for Edit/Write. Edit accepts an optional explicit hash, which remains authoritative. Text results include `startAnchor`/`endAnchor` for scoping a replacement to the displayed line range.
- You have the capability to call multiple tools in a single response. It is always better to speculatively read multiple files as a batch that are potentially useful.
- If you read a file that exists but has empty contents you will receive a system reminder warning in place of file contents.
- You can read image files using this tool.
