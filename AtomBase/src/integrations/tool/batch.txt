Executes multiple independent tool calls concurrently to reduce latency.

Payload Format:
{"tool_calls":[{"tool":"read","parameters":{"filePath":"src/index.ts","limit":350}},{"tool":"grep","parameters":{"pattern":"Session\\.updatePart","include":"src/**/*.ts"}}]}

Notes:
- 1–10 tool calls per batch
- Up to four calls run concurrently; result ordering matches input ordering
- Partial failures do not stop other tool calls
- Do NOT use the batch tool within another batch tool.
- Only read-only tools exposed to the current agent can be batched

Good Use Cases:
- Read many files
- grep + glob + read combos
- Independent web fetches and searches

When NOT to Use:
- Operations that depend on prior tool output (e.g. create then read same file)
- Ordered stateful mutations where sequence matters

State-changing tools such as bash, edit, write, agent, browser, memory, skill, and taskflow must be called directly.
