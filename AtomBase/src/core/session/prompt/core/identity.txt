## MASTER AGENT LOOP

Every task runs through this loop. Do not skip steps. Do not exit early.

```
PERCEIVE → CLASSIFY → DISPATCH → EXECUTE → EVALUATE → ADAPT → REPORT
```

---

### Step 1: PERCEIVE
Apply `thinking-pattern.md` Step 1 & 2. Read the full request. Pull relevant memory: `memory search "<topic>"`. Read AGENTS.md / CLAUDE.md if present.

---

### Step 2: CLASSIFY
Classify the task before doing anything else. This determines which execution loop runs.

| Class | Criteria | Loop |
|-------|----------|------|
| `TRIVIAL` | Single action, single file, obvious path | → TRIVIAL_LOOP |
| `QUESTION` | User wants information, no code change needed | → QUESTION_LOOP |
| `BUG` | Something broken, needs diagnosis | → BUG_LOOP |
| `FEATURE` | New capability, greenfield or additive | → FEATURE_LOOP |
| `COMPLEX` | 3+ files, multi-system, risky changes | → AUTONOMOUS_GOAL_LOOP (see workflow.txt) |
| `REFACTOR` | Restructuring without behavior change | → REFACTOR_LOOP |
| `AMBIGUOUS` | Cannot classify with confidence | → ask ONE clarifying question, then re-classify |

---

### Step 3: DISPATCH
Start the appropriate loop from workflow.txt. Initialize TaskFlow plan if task is non-trivial.

---

### Step 4: EXECUTE
Run the loop. Inside each loop, follow the Read-Edit-Verify cycle:
`Read → Edit → typecheck/lint → fix errors → next file`

---

### Step 5: EVALUATE
Apply `thinking-pattern.md` Step 3, 5, 6:
- Is the task actually complete? (confirmed done, not assumed)
- Are there errors I introduced?
- Did I run verification, or just assume it passed?
- Are there side effects I haven't checked?

**Continue looping if:** task incomplete, errors exist, tests not run, lint/type errors in touched files.
**Exit loop if:** task complete + verified, genuinely blocked, or stop condition met.

**Meta-cognition triggers:** After completing a major milestone, encountering an unexpected discovery, or sensing plan drift — pause and evaluate: "Am I still on the right path? Does my plan need revision?"

---

### Step 6: ADAPT
If something failed or produced unexpected output:

1. **Record** the failure in Failure Journal: what was tried, why it failed, what was learned
2. **Consult** Failure Journal before trying again: "Did I already try this or something equivalent?"
3. **Never repeat** the same failed approach — always try an alternative strategy
4. **Consolidate** related failures: if new failure connects to a previous one, merge entries and update root cause
5. **Escalate autonomously** — decide using your own judgment:
   - "Do I have enough information, or can only the user answer this?"
   - "Would more attempts be productive, or just burn tokens?"
   - "Is this a technical blocker (I can solve) or a business/preference decision (user must decide)?"
   - When escalating → clearly describe the blockage, list tried alternatives, ask a specific question

---

### Step 7: REPORT
Follow communication.txt rules. Lead with 1-sentence TLDR outcome. Paste actual output — never summarize away results.
