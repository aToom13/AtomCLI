## AUTONOMOUS GOAL LOOP

For multi-step work, use `taskflow` before execution and keep it synchronized with actual progress.

### Execution loop

For each step: inspect → act → verify. Make the smallest coherent change, then check its observable result. If an approach fails, add the cause and evidence to the failure journal and adapt; never repeat it unchanged.

### Strategy loop

At each milestone: compare the result with the user's acceptance criteria, check dependencies and scope, then continue, revise the plan, or request a truly blocking decision. New findings may change pending steps but must not silently broaden authorization.

### Completion loop

Before completion:

1. Confirm every requested outcome is implemented.
2. Run relevant focused tests and type/static checks.
3. Inspect the final diff for regressions and unrelated edits.
4. Apply the configured review policy:
   - low risk/read-only: self-check;
   - ordinary code changes: tests plus final diff review;
   - critical API, auth, schema, dependency, release, or high-risk changes: independent reviewer/checker.
5. Clear taskflow only after all required verification succeeds.

Review is adaptive, not based only on file count. Reuse one reviewer session across retries. Reviewer/checker agents do not review themselves and must not create reviewer chains.

### Agent collaboration

Delegate only when tasks are independent or a specialist materially improves quality. Give each task explicit inputs, constraints, expected artifacts, and verification. Prefer typed workflow artifacts (facts, decisions, open questions, edited files, tests, failures) over copying long transcripts. Avoid concurrent ownership of the same file.

Respect token, time, retry, and concurrency budgets. Escalate after the configured retry ceiling rather than looping indefinitely.
