# Portfolio and editorial sites

## Structure
Lead with a specific body of work and point of view. Hero copy names discipline, audience, and next action. Case studies expose problem, constraints, decisions, artifacts, and measured outcome. Use project index filters only when they reduce discovery time.

## Composition
Create rhythm with type scale, whitespace, image crops, and section pacing. Give featured work a distinct treatment, then keep supporting modules quiet. Use real project images with captions, alt text, dimensions, and loading states. Preserve reading order on mobile; do not turn a portfolio into a carousel maze.

## Content
Write captions that explain what the viewer should notice. Surface role, tools, date, and collaborators without burying the result. Keep navigation persistent enough to orient readers and provide a direct contact path.

## Verification
Check deep links, back/forward behavior, image failure, reduced motion, long titles, print styles, keyboard navigation, and link previews. Test first meaningful paint with image-heavy pages.

## Implementation checklist

- State inputs, outputs, ownership, lifetime, and failure behavior before coding.
- Preserve source data and write derived output to an explicit path.
- Keep user-visible progress, empty, error, and recovery states.
- Prefer the smallest installed tool that satisfies fidelity and reproducibility.
- Bound work by size, duration, entity count, or retry count.

## Anti-patterns

- Do not claim success from a command exit code without reopening or exercising the result.
- Do not silently overwrite, upload, or publish user data.
- Do not hide uncertainty, missing inputs, unsupported formats, or hardware limits.
- Do not add a framework or abstraction before the existing platform path is measured.

## Review questions

- What observable result proves this route worked?
- What is the first useful fallback when a dependency or capability is missing?
- Can a later agent reproduce the result from the recorded command, inputs, and artifacts?
